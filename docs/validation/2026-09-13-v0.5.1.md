# v0.5.1 release preparation

Base: main `423048c`, including the reviewed MCP implementation in PR #44.
Release branch: `release/v0.5.1`. The preparation changes versioning, documentation
and packaged-executable validation, with no additional runtime implementation.

## Scope

The existing CLI/TUI and one-shot JSON remain compatible. New functionality since
v0.5.0 is the optional read-only MCP server, retained snapshots, opaque observation
IDs and the Query service. Process/container actions remain out of scope.

The existing v0.5.0 live GIF remains accurate for the TUI. Snapshot IDs and MCP
structured responses are a separate interface, not new fields in one-shot JSON.

## Candidate validation

The release PR records the exact candidate commit and results of formatting,
all-target tests, Clippy, Windows compilation, release builds, clean crate
packaging/publish dry-run and Linux/native Windows CI.

The Release workflow builds both archives without publishing on a release PR or
manual dispatch. It checks SHA-256 sidecars, archive contents, extracted versions,
help and Windows console restoration. Both extracted executables now also run
the stdio MCP integration tests via `WSLTOP_MCP_TEST_EXE`, including reported MCP
server version. Real-WSL MCP collection is checked separately and is not implied
by CI's transport-only tests.

## Publication and final distribution checks

After review, merge and authorization to publish:

1. Confirm the merged commit, package version and crate VCS metadata agree.
2. Tag that exact commit `v0.5.1`; the tag workflow publishes GitHub assets.
   Publish the crate from that same clean commit.
3. Download public archives and sidecars, verify hashes and extracted versions,
   then exercise MCP from the extracted Linux and Windows executables.
4. Verify `cargo binstall` installs v0.5.1 without source fallback into an isolated
   prefix, and verify a locked crates.io source installation separately.

Public install validation cannot be completed before publication. Do not advertise
WinGet until its upstream submission is merged and the package is available.
