# v1.1.0 release preparation — 2026-10-29

## Scope and compatibility

This minor release adds the optional `--hide-windows` display filter and the TUI
`w` visibility toggle from [PR #79](https://github.com/adachi6k/wsltop/pull/79).
The filter preserves Windows collection, summary totals, CPU normalization and
the selected WSL, Docker and WSLC sources. Defaults and the four read-only MCP
tools remain unchanged. It includes the dependency and documentation updates
merged since v1.0.1.

The candidate starts from main commit
`841cb9092320470ebb4a4c85619a7916895237e6`. Cargo metadata and the changelog select
version `1.1.0`. The changelog date records preparation and must match publication.

## Real-host checks

The host runs Windows 11 Pro build 26200.9711 with 16 logical CPUs, Ubuntu
24.04.4 LTS in WSL 2, WSL/WSLC 3.0.3.0 and kernel 6.18.54.1-1.

### Visibility and interactive behavior

- Both artifacts passed eight combinations of flat/tree, text/JSON and normal/
  hidden Windows visibility. Linux flat JSON changed from 431 Windows rows to
  zero while retaining 130 WSL rows and the isolated WSLC container. The Windows
  artifact changed from 435 Windows rows to zero while retaining 65 WSL rows
  and the same WSLC container. These are separate samples and platform scopes,
  not an assertion that process counts match between executables.
- Tree JSON retained VM attribution parents, WSL/WSLC children and the 16-CPU
  host metadata while hiding Windows applications. The Linux probe also checked
  `--hide-windows --show-wsl-host`: raw VM hosts remained visible while ordinary
  Windows rows were hidden. The old, unshipped `--no-windows` name and display
  options in MCP mode were rejected as intended.
- The Linux artifact ran in a real tmux PTY in both startup visibility states.
  Actual Windows rows disappeared and returned in flat and tree views within
  0.453 seconds of each key observation, against a 15-second sampling interval.
  WSL/WSLC rows and VM parents remained. Host/Windows/WSL summary values were
  preserved; a separate session with optional collectors disabled verified the
  entire two-line summary byte-for-byte across visibility toggles. Independent
  asynchronous WSLC detail updates were not treated as filter-induced changes.
  All three sessions exited with status zero within 0.053 seconds and restored
  their original terminal modes.
- The native Windows artifact ran in a native ConPTY with read/write console
  handles, also in both startup visibility states. Actual flat/tree Windows
  rows changed within the 357–360 ms observation window after `w`, against a
  30-second sampling interval. CPU/RAM summaries remained identical across each
  visibility toggle. Default Ubuntu discovery and initial loading were observed.
  Both sessions exited with `q` in 23 ms and restored the alternate screen and
  original input/output console modes.
- Initial screen-analysis assertions exposed limitations in an old ANSI parser
  and an incorrect expected VM display label. Linux screenshots were verified
  with tmux and native ConPTY captures with a VT terminal emulator. No product
  code changes were needed to pass the corrected probes.
- The test WSLC container used a cached image without network access or mounts.
  It was removed after both platforms completed verification. A subsequent
  Linux artifact collection reported 130 WSL rows, zero WSLC rows and no warnings.
  Existing containers and processes were not stopped or reconfigured.

### CPU and MCP

- With the Linux artifact and `--wsl-only --cpu-scale host`, one and four
  disposable CPU workers measured 6.2416% and 24.9709% in total on the 16-CPU
  host. Independent `/proc` process-time deltas agreed within 0.03 percentage
  points per worker. This checks normalization against the controlled work;
  it does not assert equality with independently sampled Task Manager totals.
  All test workers were stopped.
- The Linux artifact passed all three `mcp_stdio` integration tests, including
  the explicitly enabled live observation round trip. The Windows artifact
  passed a live round trip through all four read-only tools, pinned-snapshot
  reuse, host CPU/RAM metadata and clean EOF. CI also passed its packaged
  Windows MCP transport tests.

### Optional sources and coverage limits

- Removing `wslc.exe` from only the probe's PATH preserved Windows/WSL collection
  without WSLC rows. Restoring the inherited environment recovered the test
  container's WSLC row.
- A per-process `DOCKER_HOST` pointing to a nonexistent socket preserved
  Windows/WSL collection without Docker rows. The normal Linux socket and
  Windows named-pipe endpoints were also unavailable on this host. No Docker
  daemon was started or reconfigured. Live Docker container-row retention and
  recovery to a reachable daemon were not repeated; row retention is covered
  by automated filter tests, and the unchanged collector's reachable-daemon
  behavior is recorded in the [v1.0.1 validation](2026-10-24-v1.0.1.md#exact-artifact-real-host-checks).
- The isolated WSLC container ran on a different kernel from the primary WSL
  distribution. The existing `WSL*` unresolved-overlap warning appeared and
  inclusive observations were preserved in both visibility modes. No claim of
  resolved attribution for this topology is made.
- The new feature and representative release paths were exercised directly.
  Unchanged sorting, selection and other feature-matrix behavior retain the
  automated regression coverage and prior dated validation records; every
  possible container topology and interactive action was not repeated here.
