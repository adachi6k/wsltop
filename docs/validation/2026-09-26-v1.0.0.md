# 1.0 release validation — 2026-09-26

## Candidate and compatibility boundary

The published `v1.0.0-rc.1` candidate is commit
`43c8af8869d5a572e15e015f7b1b34e909acc0f2` ([PR #60](https://github.com/adachi6k/wsltop/pull/60)).
It includes the previously merged primary-WSL normal termination feature and
the rmcp 3.4 update. The [compatibility policy](../compatibility.md) defines the
1.x boundary; existing CLI flags, flat/tree JSON fields and units, and four
read-only MCP tools were retained. No additional action tools or roadmap
features were made release prerequisites.

## Completed RC checks

- Local formatting, Clippy (all targets/features), 231 unit and two integration
  tests passed. Three release-note test cases cover stable/RC extraction,
  pinned documentation links and invalid/missing release metadata.
- `cargo package --locked --offline` and `cargo publish --dry-run --locked`
  passed. The exact RC tag was published to crates.io.
- [RC PR workflows](https://github.com/adachi6k/wsltop/actions/runs/36222939609)
  and [tagged release workflow](https://github.com/adachi6k/wsltop/actions/runs/36223220771)
  passed. They cover both native builds, extracted archive contents and versions,
  SHA-256 checks, packaged MCP transport and Windows console restoration.
- Both public archives were downloaded and their SHA-256 sidecars verified.
  Linux installation using `cargo-binstall --version 1.0.0-rc.1` fetched the
  published GitHub binary into an isolated install directory.
- Installed Linux and extracted Windows MSVC executables passed help/version,
  flat/tree JSON checks, MCP discovery, all four tools against real observations,
  pinned-snapshot inspection and clean EOF. The Windows run used Ubuntu as
  primary WSL; Linux used WSL-only mode. Docker and WSLC were disabled for these
  checks. One initial Windows collection attempt failed; a repeat completed all
  JSON and MCP checks. These checks do not establish collector availability
  under every workload.
- The public Windows MSVC TUI selected a disposable, uniquely named process
  in Ubuntu. The confirmation showed its exact PID and name. Cancel left the
  process alive; a subsequent explicit confirmation sent SIGTERM, observed exit
  and returned cleanly from the TUI. Linux-native action rejection left the
  test target alive. Both returned from the alternate terminal screen.
- Stale identity, permission, namespace and unsupported-helper cases remain
  covered by the existing backend tests and the separate
  [process termination validation](2026-09-26-process-termination.md).

## Final presentation adjustment

[PR #61](https://github.com/adachi6k/wsltop/pull/61) dims the footer menu using
terminal dim intensity, keeping action feedback at normal intensity and
monochrome output unstyled. A fresh local build was checked in live terminals:
the color footer emits SGR dim styling; `--color never` does not. All 19 existing
TUI tests and the PR's Linux/Windows CI and release packaging checks passed.
This is the only application-code change between the RC and the stable release.

The stable release PR updates version metadata, documentation and these notes.
Its CI and non-publishing release workflow must pass before tagging `v1.0.0`.
The tagged workflow repeats packaging validation before public assets are
uploaded. These are release gates, not claims that future publication has
already completed.
